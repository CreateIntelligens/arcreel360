# 劇集工作區三階段拆分 + 原文並排設計

**日期**: 2026-06-04
**狀態**: Draft

## 概述

把 `TimelineCanvas` 目前的兩 tab（`preprocessing` / `timeline`）重構成**三階段 tab**，並讓每個 segment panel 旁可並排對照原文。

```
現狀：[預處理]  [時間線(分鏡圖+影片混在每張 SegmentCard)]
目標：[預處理]  [分鏡圖]      [影片]
      域處理     storyboard    video
```

核心原則：**三階段共用同一批 segment panel 與同一時間軸**。切 tab 不是換資料、而是換「同一組 panel 的聚焦視圖」——分鏡圖 tab 只露出分鏡圖相關區塊，影片 tab 只露出影片相關區塊，但 panel 順序、選取、滾動位置不變。

## 動機

- 目前每張 `SegmentCard` 同時渲染分鏡圖區 + 影片區，但實際工作流是「先全部做分鏡圖、再全部做影片」兩個明顯不同的步驟。混在一張卡讓使用者無法聚焦單一階段。
- 使用者需要對照原文檢查分鏡是否貼合原著，目前 UI 無原文對照。
- 為未來角色三視圖（turnaround）預留資料結構空間。

## 範圍決策（brainstorming 結論）

| 議題 | 決定 |
|------|------|
| 拆分主軸 | **Tab 階段拆成三段**（預處理→分鏡圖→影片），非卡片內拆 |
| 原文用途 | **UI 並排對照**，供手動檢查/調 prompt，**不餵 AI** |
| panel 同步 | **三階段共用同一批 panel**，切 tab 保持滾動位置/選取 |
| 首幀切版（C） | 影片 tab 的首幀來源縮圖**可切換分鏡圖版本**（接 VersionTimeMachine） |
| 卡片模型下拉（D） | 每張卡片一個**直接下拉選單**選模型；分鏡圖 tab 露圖片模型、影片 tab 露影片模型；取代現有 SceneBackendPopover |
| 三視圖 | **本期只預留設計空間**，不實作生成 |
| 階段條範圍 | **頂層 + timeline 一起動**：頂層 phase 跳轉對應到 timeline tab |

## 設計

### 組件 1：Tab 狀態機（TimelineCanvas）

`activeTab` 改為 `"preprocessing" | "storyboard" | "video"`。

- **`defaultTab` 邏輯**：
  - 無劇本 → `preprocessing`
  - 有劇本、分鏡圖未全完成 → `storyboard`
  - 分鏡圖全完成 → `video`
  - 與後端 `status.current_phase` 對齊（`storyboard` / `video` 字串已由 phase-split 設計提供）。
- **頂層 phase 跳轉**：`GlobalHeader.handlePhaseNavigate` 點 `storyboard` 進分鏡圖 tab、點 `video` 進影片 tab。透過共用 store（或導航 query 參數）把目標 tab 傳給 TimelineCanvas。
- **滾動/選取同步**：把「目前選取的 segmentId」與滾動位置提升到 TimelineCanvas 層級的共用 state，三 tab 共享。切 tab 後用 `scrollIntoView` 把同一 panel 對齊回原位。

### 組件 2：SegmentCard 的階段聚焦

SegmentCard 新增 `stage: "storyboard" | "video"` prop：

- `stage="storyboard"`：露出分鏡圖（首幀圖）+ `image_prompt` 編輯 + 生成/重生按鈕；影片區隱藏。
- `stage="video"`：露出影片 + `video_prompt` 編輯 + 生成按鈕；分鏡圖縮為唯讀縮圖（標示「首幀來源」）。

資料模型不變（仍是同一個 segment 含 `image_prompt`/`video_prompt`），只按 stage 過濾視圖。

### 組件 3：原文並排（對照用，不餵 AI）

在分鏡圖/影片 tab，每個 segment panel 旁顯示對應**原文段落**，供對照檢查、手動調 prompt。

- **資料來源（採方案 A）**：並排顯示**預處理 Step 1 段落**（`step1_segments.md` / `step1_normalized_script.md`），而非生 source。對應關係靠**順序索引**（第 N 個 panel 對第 N 段）。成本低、不需新資料結構。
  - 方案 B（segment 上加 `source_ref` 精準 char-range 對應）成本高，**本期不採**，留待未來升級。
- **UI**：panel 旁一欄可收合的「原文」側欄（預設收合，避免擠壓 panel 寬度）。點開顯示該 segment 對應的 Step 1 段落，唯讀、可複製。
- **取得方式（已確認無需新端點）**：`GET /projects/{name}/drafts/{episode}/step{step_num}`（`files.py:506`）已存在，前端 `API.getDraftContent(projectName, episode, 1)` 已在 `PreprocessingView.tsx:32` 使用。原文側欄直接複用，**不需新增後端端點**。

### 組件 3.5：原文不餵 AI（明確界定）

原文側欄純對照，**不進任何生成 prompt**：

- 分鏡圖生成吃 `image_prompt`（`generation_tasks.py:_normalize_storyboard_prompt` → `image_prompt_to_yaml`，只組 prompt + style）。
- 影片生成吃 `video_prompt`。
- 原文側欄與上述兩條生成路徑**無資料連線**。使用者可看著原文手動編輯 prompt，但系統不自動串接。
- 最原始（既有）作法也**未**把原文送進生成——本設計維持此行為，不改變。

### 組件 5：影片首幀切版（C，新增）

影片 tab 的「首幀來源」唯讀縮圖目前固定顯示最新分鏡圖。改為**可切換分鏡圖版本**：

- 接既有 `VersionTimeMachine`（`frontend/src/components/canvas/timeline/VersionTimeMachine.tsx`，分鏡圖版本歷史 + 回滾）。
- 在 video stage 的首幀縮圖旁加版本切換入口，使用者可選定哪一版分鏡圖作為影片首幀來源預覽。
- **資料層**：沿用既有 storyboard 版本機制（`versions` API / VersionManager）。先確認「指定某版分鏡圖給影片首幀」是否已有資料欄位；若影片首幀恆取「目前主版分鏡圖」，則切版即「把該版設為主版」，不需新欄位。若要影片首幀與分鏡圖主版解耦（各自獨立指定），則需在 segment 上加 `video_start_version`——**本期先採「切版＝設主版」最小做法**，解耦留待後續。

### 組件 6：每張卡片直接模型下拉（D，新增）

把目前的 `SceneBackendPopover`（要開 popover、內含圖片+影片兩個後端並排）改為**卡片內直接下拉**：

- 分鏡圖 tab 的卡片：一個 `ProviderModelSelect`（圖片模型，options 過濾 `media_type === "image"`），值綁 `segment.image_backend`。
- 影片 tab 的卡片：一個 `ProviderModelSelect`（影片模型，`media_type === "video"`），值綁 `segment.video_backend`。
- **複用既有元件與資料流**：`ProviderModelSelect`（`frontend/src/components/ui/ProviderModelSelect.tsx`）已是按 provider 分組的下拉；後端單鏡頭 override 已支援（`generate.py:79` `_read_scene_backend_override`，優先序 scene > episode > project > 系統預設）。**不需改後端**。
- 寫入沿用 SceneBackendPopover 既有的儲存路徑（onChanged → PATCH segment backend）。
- `SceneBackendPopover` 由卡片內下拉取代後移除（或保留 episode 級 `EpisodeOverridesPopover` 不動，僅換掉場景級 popover）。
- 空值（未選）顯示「專案預設模型」選項，對齊 `EpisodeOverridesPopover` 既有 `{ value: "", label: "專案預設模型" }` 模式。

### 組件 4：三視圖預留（本期不實作）

僅在資料結構與 UI 留口子，不寫生成邏輯：

- 角色/場景參考圖欄位設計成**可多張**（若目前單張，介面預留 array 形狀），未來 turnaround 正/側/背各一張能直接塞入。
- 不動生成 prompt、不加按鈕。確保未來加三視圖時不用改資料模型。
