# 參考圖移除 + 分鏡參考圖上傳 設計

> 狀態：Draft
> 日期：2026-05-29
> 兩個相關功能一起設計，共用 `LorebookReferenceImageField` 組件與既有 v0 基底機制。

## 背景

### 現況（已查證）

**參考圖共用組件** `frontend/src/components/canvas/lorebook/LorebookReferenceImageField.tsx`：
- 只有「上傳 / 替換 / 更換」，**沒有移除**。`onUpload` 只接受 `File`。
- 被 `CharacterCard` / `ClueCard` / `SceneCard` 使用（圖鑑三者）。**分鏡（timeline）沒用它，也沒有任何參考圖上傳 UI。**

**角色/線索/場景上傳參考圖的後端機制**（`server/routers/files.py`）：
上傳一張參考圖時，後端做兩件事：
1. 設 `reference_image` 欄位（路徑如 `characters/refs/XXX.jpg`）——`METADATA_UPDATE_METHODS` 的 `*_ref` 方法。
2. `vm.set_base_version(resource_type, name, ref_abs, prompt="使用者上傳")`（files.py:143）——把上傳圖存成版本系統的 **v0 基底**（`character_sheet` 指向 `versions/characters/XXX_v0.png`）。

`_FIELD_MAP` / `METADATA_UPDATE_METHODS` 目前涵蓋 `character_ref` / `clue_ref` / `scene_ref`，**無 `storyboard_ref`**。

**VersionManager**：`RESOURCE_TYPES` 已含 `storyboards`，`set_base_version` 技術上支援分鏡，無需改 VersionManager。

**分鏡生成參考圖收集** `server/services/generation_tasks.py` 的 `_collect_reference_images`：
帶入 角色 sheet + 線索 sheet + 場景 sheet + 前一張分鏡圖（`previous_storyboard_path`）。
**目前不會把「本分鏡自己的 v0 基底」當參考圖。**

### 關鍵事實（已查證）

`*_sheet` 欄位**就是 v0 基底**——上傳參考圖時 `_promote_reference_to_base_version`（files.py）：
1. `set_base_version(...)` 存成 `versions/<type>/<name>_v0.png`（v0 基底）；
2. sheet 欄位（character_sheet 等）指向該 v0；
3. `reference_image` 另存原始檔路徑（`refs/`，僅供 UI 顯示/追溯）。

**生成時 `_collect_reference_images` 讀的是 sheet（=v0），不是 reference_image。**
因此「移除參考圖回純文字」必須清掉 v0 / sheet，光清 reference_image 無效。

### 使用者已確認的決策

- **A 移除語義（最終）**：**連 v0 版本記錄一起清** — 清空 sheet 欄位 + reference_image 欄位 +
  versions.json 的 v0 記錄 + 實體 v0 檔。徹底回到純文字生成。**不保留、不可復原**（使用者明確選擇）。
- **B 機制**：分鏡上傳參考圖 = **複用角色/線索同一套**（`set_base_version` 設為 v0 基底 + sheet 指向），**非**多張附加。一張。
- 兩功能共用 `LorebookReferenceImageField` 組件（A 的移除鈕對四種資源一次到位）。

## 設計目標

1. **A**：`LorebookReferenceImageField` 加「移除」，清空對應資源的 `reference_image` 欄位；角色/線索/場景立即受益。
2. **B**：分鏡（storyboard）支援上傳參考圖，走與角色相同的 `set_base_version` + `reference_image` 路徑，存為該分鏡 v0 基底；生成分鏡時把此 v0 基底納入參考清單。

### 非目標

- 不做多張 `extra_reference_images` 附加 UI（使用者選了 v0 基底單張模式）。
- 不刪實體檔（移除只解除關聯）。
- 不改費用/解析度等其他功能。

## A. 參考圖移除

### A1. 共用組件加移除
`LorebookReferenceImageField.tsx`：
- props 加 `onRemove?: () => Promise<void> | void`（optional——未傳則不顯示移除鈕，向後相容）。
- 已有參考圖時，在「替換」旁加「移除」按鈕（紅色系，hover 提示）。
- 點移除 → 呼叫 `onRemove`，清空本地 `referenceFile`/`referencePreview`，回到「上傳參考圖」空狀態。

### A2. 各 Card 接上 onRemove
`CharacterCard` / `ClueCard` / `SceneCard`：各加一個 `onRemoveReference(name)` 回呼，
呼叫對應的更新 API 把 `reference_image` 設為空字串/null。

### A3. 後端徹底清除 v0（新端點或擴充既有）
移除 = 清這四項，需一個「清除參考圖」後端操作（建議新端點，或擴充 metadata 端點接受清除指令）：
1. **versions.json 的 v0 記錄** — 透過 VersionManager 移除該資源的 v0（需新增 VersionManager 方法，
   例如 `remove_base_version(resource_type, resource_id)`，刪 v0 record + 若 current_version==0 重設）。
2. **實體 v0 檔** — 刪 `versions/<type>/<name>_v0.png`。
3. **sheet 欄位** — 清空 character_sheet / clue_sheet / scene_sheet（設為 ""）。
4. **reference_image 欄位** — 清空（設為 ""）。

完成後 `_collect_reference_images` 因 sheet 為空，不再帶入該資源 → 純文字生成。

> 邊界：若該資源已有 AI 生成版本（v1+），移除 v0 是否影響 current？
> 設計決定：只移除 v0；若 current_version==0（只有上傳基底、沒生成過），移除後該資源無圖（回未生成狀態）；
> 若已有 v1+，current 指向最新 AI 版本不受影響（但 sheet 清空會讓生成不以 v0 為基底——符合「不參考」意圖）。
> 實作者需在 VersionManager 方法內處理 current_version 的重算，並寫測試覆蓋「只有 v0」與「有 v1+」兩情境。

### A4. 測試
- 組件：有 `onRemove` 時顯示移除鈕、點擊呼叫回呼並回空狀態；無 `onRemove` 不顯示。
- 各 Card：移除呼叫清除 API。
- 後端：清除後 versions.json 無 v0、實體檔已刪、sheet/reference_image 為空；
  `_collect_reference_images` 不再帶入該資源（兩情境：只有 v0 / 有 v1+）。

## B. 分鏡上傳參考圖（v0 基底）

### B1. 後端：files.py 加 storyboard_ref 映射
`_FIELD_MAP` 加 `"storyboard_ref": "storyboard"`（或對應 scene id 機制）。
`METADATA_UPDATE_METHODS` 加 `"storyboard_ref"`：分鏡參考圖的 reference_image 存哪需確認——
分鏡資料在 script 的 scene item，非 project.json 的 entity dict。
**設計決定**：分鏡參考圖路徑存進 scene item 的新欄位 `reference_image`（與 image_backend 同層），
並透過 `set_base_version("storyboards", segment_id, ...)` 設為該分鏡 v0 基底。
需新增/沿用一個能寫 scene item 欄位的更新方法（參考既有 update_scene_backend 模式）。

### B2. 後端：生成時納入本分鏡 v0 基底
`_collect_reference_images` 增加一條：若本分鏡存在 v0 基底（使用者上傳的參考圖），
將其加入 reference_images 清單（附加在角色/線索/場景 sheet 與前一張圖之外，與使用者「附加」直覺一致）。
- 來源：`VersionManager.get_versions("storyboards", segment_id)` 的 v0，或 scene item 的 `reference_image` 路徑。
- 優先用 scene item 的 `reference_image`（單一真相），存在則 append。

### B3. 前端：SegmentCard 加參考圖上傳
`SegmentCard.tsx` 分鏡圖區（storyboard 區塊，約 line 886）加入 `LorebookReferenceImageField`：
- `savedUrl` = scene item 的 `reference_image` 經 `API.getFileUrl`。
- `onUpload(file)` → 呼叫上傳 API（field=`storyboard_ref`, resource_id=segmentId）。
- `onRemove`（複用 A1）→ 清空該分鏡的 reference_image。

### B4. 測試
- 後端：上傳 storyboard_ref → scene item reference_image 寫入 + v0 基底建立；
  `_collect_reference_images` 帶入該 v0。
- 前端：SegmentCard 顯示上傳區、上傳呼叫正確 API、移除清空。

## 待實作前確認（不可跳過）

1. **VersionManager 缺移除 v0 的方法**：目前有 `set_base_version` 但無對應的移除。A3 需新增
   `remove_base_version`（刪 v0 record + 實體檔 + 重算 current_version）。實作者先確認沒有現成方法可複用。
2. **B 的移除一致性**：分鏡與角色/線索採同一移除語義（連 v0 一起清）。分鏡的 reference_image 存 scene item，
   移除時 scene 欄位 + storyboards v0（versions.json + 實體檔）一起清。
