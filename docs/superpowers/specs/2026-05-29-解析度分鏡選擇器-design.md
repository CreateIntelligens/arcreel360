# 圖片解析度 + 影片解析度分鏡選擇器設計

> 狀態：Draft
> 日期：2026-05-29
> 前置：本設計是「生成參數可配置化」系列的一部分。影片**秒數**選擇器已於 `2026-04-06-video-duration-selection-design.md` 完成，本設計不重做。

## 背景

使用者希望在生成圖片/影片時能選解析度，且解析度依模型能力動態變化。盤點現況後，本系列拆成 A/B/C 三塊，本文件只涵蓋 A 的剩餘工作。

### 現況盤點

| 項目 | 狀態 |
|---|---|
| 影片**秒數**選擇器（依模型/解析度動態 + 不合法自動修正） | ✅ 已做：`SegmentCard` 的 `DurationSelector` + `useVideoDurationOptions` |
| 影片**解析度** | ⚠️ 部分：`useVideoResolutionOptions` hook 存在；全域在 `ProjectSettingsPage` 可選（存 `project.video_model_settings[model].resolution`）；**分鏡層級的解析度選擇器 UI 缺**（`TimelineCanvas` 只讀 `currentVideoResolution`，無法在分鏡上改） |
| 圖片**解析度** | ❌ 全程 hardcode `image_size="1K"`；registry 無 `supported_image_sizes`；完全沒有 |

### 能力 metadata 機制（已存在，沿用）

`lib/config/registry.py` 的 `ModelInfo` 已有 `supported_durations` / `supported_resolutions` / `duration_resolution_constraints`，並經 `server/routers/providers.py` 的 `ModelInfoResponse` 下發前端（`frontend/src/types/provider.ts`）。本設計沿用同一條鏈路，新增圖片尺寸能力欄位。

## 設計目標

1. 圖片可依模型支援的尺寸選解析度（如 `["480p","720p"]` 或 `["1K","2K"]`），各模型自行宣告。
2. 影片解析度可在分鏡層級選擇（per-scene 覆蓋），補齊現有缺口。
3. per-scene 覆蓋存進 script 的 scene item，沿用現有 `image_backend`/`video_backend` 同層欄位模式。
4. 生成時用 per-scene 覆蓋取代 hardcode 的 `image_size="1K"` 與影片解析度 fallback。
5. 向後相容：未設定覆蓋的舊資料沿用上層預設；新欄位皆 optional。

### 非目標（明確排除）

- 全域圖片/影片解析度預設的完整整合 → 屬於 B（全域預設 + 分鏡覆蓋的統一機制）。本文件只做分鏡層級；圖片全域預設僅順帶在現有 `ProjectSettingsPage` 接上（見 §4）。
- 影片模式（首尾幀 / 全模態，Seedance）→ 屬於 C，另開設計。
- 影片秒數選擇器 → 已完成，不動。

## 1. 圖片尺寸能力宣告

### 1.1 ModelInfo 擴充

`lib/config/registry.py`：

```python
@dataclass(frozen=True)
class ModelInfo:
    display_name: str
    media_type: str
    capabilities: list[str]
    default: bool = False
    supported_durations: list[int] = field(default_factory=list)
    duration_resolution_constraints: dict[str, list[int]] = field(default_factory=dict)
    supported_resolutions: list[str] = field(default_factory=list)
    reference_image_force_duration: int | None = None
    supported_image_sizes: list[str] = field(default_factory=list)  # 新增
```

語意：僅對 `media_type == "image"` 的模型有意義。空清單 = 沿用現狀（前端 fallback 到 `["1K"]`，不顯示選擇器或只顯示單一選項）。

### 1.2 各圖片模型填值（本輪保守值）

所有現有圖片模型先填 `["1K"]`（等於現狀，不改變行為）。實際支援的低解析度（480p/720p 等）由使用者後續依各模型文件補上。本輪不臆測。

### 1.3 自定義供應商（本輪排除）

`CustomProviderModel`（`lib/db/models/custom_provider.py`）目前只有 `supported_durations`，**沒有** `supported_resolutions`，圖片尺寸宣告基礎本就不完整，且新增欄位需 DB migration。本輪**不**為自定義供應商加 `supported_image_sizes`——自定義圖片模型一律 fallback 到 `["1K"]`（現狀）。待 B 階段統一補齊自定義供應商的解析度/尺寸能力欄位（含 migration）。

```python
supported_image_sizes: list[str] = []
```

並在組裝 response 處透傳 `meta.supported_image_sizes`。

`frontend/src/types/provider.ts` 的 `ModelInfoResponse` 對應新增 `supported_image_sizes: string[]`。

## 3. 圖片尺寸選項 hook

仿照 `useVideoResolutionOptions`，新增 `frontend/src/hooks/useImageSizeOptions.ts`：

```
useImageSizeOptions(imageBackend: string | null | undefined): string[] | null
```

- 輸入 `provider/model` 字串；查 providers → 該 image model 的 `supported_image_sizes`。
- 空或查無 → 回傳 null（呼叫端 fallback 到 `["1K"]`）。
- 純讀取、無副作用，便於單測。

附對應測試 `useImageSizeOptions.test.tsx`（有宣告 → 回傳清單；無宣告 → null；非圖片模型 → null）。

## 4. 選擇器 UI

### 4.1 影片解析度 — 分鏡層級（補齊）

在 `SegmentCard.tsx` 仿 `DurationSelector` 新增 `ResolutionSelector`：

- 選項來自 `useVideoResolutionOptions(videoBackend)`，fallback `DEFAULT_RESOLUTIONS`。
- 值寫回 scene：`onUpdatePrompt(segmentId, "video_resolution", value)`。
- **與秒數連動**：解析度變更後，沿用現有 `effectiveDurationOptions` 的重算路徑（`useVideoDurationOptions` 已吃 resolution 參數），若當前秒數不在新解析度允許範圍，現有的「自動修正 + toast」邏輯會處理。本設計只需確保 `ResolutionSelector` 改值會觸發該重算（把選定 resolution 餵進 `useVideoDurationOptions` 的 `currentResolution`）。

### 4.2 圖片解析度 — 分鏡層級（新增）

`SegmentCard.tsx` 圖片區（分鏡圖那塊）新增 `ImageSizeSelector`：

- 選項來自 `useImageSizeOptions(imageBackend)`，fallback `["1K"]`。
- 單一選項時可不顯示或顯示為唯讀 chip（避免無意義下拉）。
- 值寫回 scene：`onUpdatePrompt(segmentId, "image_size", value)`。

### 4.3 圖片解析度 — 全域（順帶）

`ProjectSettingsPage.tsx` 已有影片解析度全域設定模式（`video_model_settings[model].resolution`）。圖片比照新增 `image_model_settings[model].image_size`，存進 `project.json`。此為順帶接上，避免圖片只有分鏡能設、全域不能設的割裂感。**若實作時發現牽連過大，可降級為僅分鏡層級，全域留給 B。**

## 5. 持久化與生成流程

### 5.1 per-scene 覆蓋儲存

新欄位直接寫在 script 的 scene item 上，與 `image_backend`/`video_backend` 同層：

- `image_size`：字串，如 `"720p"`
- `video_resolution`：字串，如 `"1080p"`

（影片秒數 `duration_seconds` 已存在於 scene item，不動。）

### 5.2 讀取覆蓋

`server/routers/generate.py` 已有 `_read_scene_backend_override` 模式讀 scene 欄位。比照新增讀取 `image_size` / `video_resolution` 的 helper（或泛化現有 helper 接受任意欄位名），放進生成 payload。

### 5.3 生成時套用

- **圖片**：`server/services/generation_tasks.py` 目前多處 hardcode `image_size="1K"`（storyboard / character / clue）。改為：`payload` 帶 scene 覆蓋的 `image_size` → 無則 fallback `"1K"`。
- **影片**：解析度已從 `model_settings.get("resolution")` 讀；補上 scene 覆蓋的 `video_resolution` 優先序高於 model_settings。

### 5.4 解析度優先序

```
scene 覆蓋 > 專案級（model_settings / image_model_settings）> 模型預設 / hardcode fallback
```

與現有 backend 解析的優先序模式一致。

---

## 6. 錯誤處理 / 邊界

- 選定解析度不在模型 `supported_*` 清單（例如換了模型導致舊覆蓋失效）：生成前以模型能力校驗，不合法則 fallback 到該模型第一個合法值（圖片）；影片沿用既有 `VeoInvalidCombinationError` 校驗路徑。
- 單一選項時 UI 不強迫使用者操作（唯讀顯示）。
- 空 `supported_image_sizes` → fallback `["1K"]`，行為與現狀一致。

## 7. 測試

**後端**
- registry：圖片模型含 `supported_image_sizes` 欄位（預設 `["1K"]`）。
- providers API：response 含 `supported_image_sizes`。
- generation_tasks：scene 覆蓋的 `image_size` / `video_resolution` 確實取代 hardcode；無覆蓋時 fallback 正確。
- generate.py：scene 覆蓋讀取 helper 行為（有值/無值/script 不存在）。

**前端**
- `useImageSizeOptions`：有宣告/無宣告/非圖片模型三情境。
- `ImageSizeSelector` / `ResolutionSelector`（分鏡）：渲染選項、選值回呼正確、單一選項唯讀。
- 連動：分鏡解析度變更後秒數重算路徑被觸發（沿用現有測試模式）。
